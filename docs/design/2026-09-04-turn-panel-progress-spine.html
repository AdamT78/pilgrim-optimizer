The settled row set, drawn at real widths, with the six open questions worked as alternatives rather than described. Every sentence shown is an existing server string: ROUTE_PROMPT, DUTY_PROMPT, SKIP_PROMPT, ORIGIN_PROMPT, RESOLUTION_PROMPT and the Beginning-of-Turn sentence, all quoted from tools/play_server.py:1332–1341 and :4131. The stage labels are yours. Nothing here is composed, joined or inflected, and the one place I do ask for something new is called out and priced at the bottom.

One thing worth knowing before choosing

The single-question rule is eight lines, not an architecture. promptsOf() at play_view_turn.js:1363 walks the offered steps and returns the first prompt it finds, as a one-element array. Its consumer, mark(prompts, 'data-turn-prompt', promptsOf(offered)), already takes a list and already reveals every element whose value is in it.

So “show both questions” is: return the distinct prompts instead of the first. Every prompt row is already printed into the DOM. Those 95 positions are not a new capability; they are a return statement.

Colour answers one question only — is this now? The gutter answers the other: ✓ answered, – nothing to answer, blank still to come. Four states, two channels, and the ticks accumulate into a progress read you get without reading a word.

open now — #F2EEDF, 600 weight, seat bar
ahead — #6B675E, no glyph
answered — #6B675E, ✓
nothing to answer — #46433C, –

Answered should not dim further. The trail is the thing a returning player reads first — what have I already done this turn — and a second grey buys nothing that the tick does not already say. Keeping answered and ahead on one colour also means the column has exactly two brightnesses, which is what makes the open row findable without looking.

Drop the strike. It is the only treatment here that damages the letterforms, and at this size in a dark column it costs more legibility than it earns. The dash says the same thing and stays quiet.

Keep the slot, let the server empty it. “Take a duty / Choose a duty to take.” is a real duplication and the panel is narrow enough to feel it. But deciding that a sentence duplicates a label is exactly the kind of judgement the page must not make — it would be comparing two strings and inferring meaning. The cheap version is a boolean on the step, something like prompt_restates_stage, set where the two strings are authored, next to each other, by the person who can see both. No new sentence, no new wording-inventory entry, and the page keeps doing what it does today: revealing what it is told to reveal.

If that flag is not worth it, the second option is still correct and the duplication is survivable — it costs one line of vertical space in a panel that has just stopped changing height.

5 · Type

5

Four levels, four sizes

SOW11px, 600, +.09em, #4E4A43 — phase. The smallest and quietest thing in the column, because it is a container label, not a position. Uppercase is a text-transform; the string is untouched.
Walk the route12.5px, #6B675E — stage, not now.
Take a duty12.5px, 600, #F2EEDF — stage, open. Same size; weight and brightness carry it, so nothing moves when a row opens.
Choose a duty to take.13.5px — question. The largest text in the panel, because it is the only sentence that asks for something.
Confirm13px — control.
Pick up acolytes for sowing. Buildings can be used here — some free, some hired.11.5px, #9A9486 — standing note. The phase sentence, which describes rather than asks.

The inversion is deliberate: the phase is the smallest type in the column and the question the largest. Phase names change rarely and are read once; the question changes constantly and is the reason the panel exists. Today all four levels sit at 12–13px and the only differentiated element is the question, differentiated by a colour that is hard to read.

Two sizes total for the spine (11 and 12.5) keeps the nesting legible without the indent having to do all the work — useful at 270px, where the indent is expensive.

The setup phase is a different question and your answer to it is right. There, the phase genuinely has a different shape — the stages do not exist — and drawing rows for stages that cannot occur would be inventing structure. Here the stage exists, has been reached or will be, and happens to be empty. Absent for “not part of this phase”, present and marked for “part of this phase, nothing in it”. One rule, two outcomes, and the height only changes when the phase changes.

What this costs

?

Priced against your registers

Free. Everything carrying meaning here is colour, weight, indentation, a 3px rule and two glyphs: the two-brightness scheme, the spanning bar, the tick and dash gutter, the type scale, questions sitting under their rows, the empty-stage marking. No string is added or changed for any of it.

One line of client. promptsOf() returns the distinct prompts of the offered steps rather than the first. mark() already accepts a list and every prompt row is already in the DOM, so nothing else in the reveal path changes.

One string edit, in the cheap register. Stop prepending the seat prefix in decision_steps. The sentence tails are already authored without it; this removes a join rather than adding wording.

One new field, and only if you want it. A boolean on the step — prompt_restates_stage or similar — so the question slot can be left empty for “Take a duty / Choose a duty to take.” It is not a sentence and adds no wording-inventory entry, but it is a payload field with a test, so it should only be spent if the duplication actually grates in play. Everything else works without it.

What I did not propose, and why. No progress count, no breadcrumb, no “2 of 4”, no stage name repeated inside a question — the gutter ticks give the count as a shape, and position gives the breadcrumb. The one thing structure genuinely cannot say is which of two similar strings is redundant, which is why that is the only place I asked for anything new.
